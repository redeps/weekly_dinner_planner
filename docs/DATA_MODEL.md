# Data Model — Meal Planner

This document describes the conceptual relational schema. It is intentionally
implementation-agnostic about exact SQLite column types where it doesn't
matter, but the tables, keys, and separation of concerns described here are
required — see `docs/AGENT_INSTRUCTIONS.md`.

The Foundation prototype (Milestone 0) does **not** yet create these tables —
`database.py` currently only proves that SQLite is reachable from the app.
Milestone 1 introduces `recipes`. Milestone 2 introduces
`recipe_ingredients`. Milestone 4 introduces `week_plans` and `plan_days`.
Milestone 7 introduces `cook_history`.

## RECIPES

| column              | type      | notes                                            |
|---------------------|-----------|----------------------------------------------------|
| id                  | integer PK |                                                    |
| name                | text      |                                                    |
| photo_path          | text, nullable | relative path under `photos/`                 |
| cook_time_minutes   | integer   |                                                    |
| family_enjoyment    | integer   | e.g. 1–5 rating                                     |
| seasonality         | text      | winter / spring / summer / fall / all-season        |
| is_quick_fallback   | boolean   | true = low-effort seed option (frozen pizza, takeout, etc.); a signal to the generator, not a separate table |
| servings            | integer   |                                                    |
| instructions        | text, nullable | ordered steps, free text                       |
| notes               | text, nullable |                                                    |
| active              | boolean   | soft-disable instead of delete                     |
| created_at          | timestamp |                                                    |
| updated_at          | timestamp |                                                    |

## RECIPE_INGREDIENTS

Structured ingredient lines. Kept separate from `recipes` so the grocery
list can be generated by aggregation instead of parsed from free text.

| column          | type      | notes                                           |
|-----------------|-----------|---------------------------------------------------|
| id              | integer PK |                                                   |
| recipe_id       | integer FK → recipes.id |                                      |
| name            | text      | e.g. "chicken thighs"                              |
| quantity        | number    |                                                   |
| unit            | text      | e.g. "g", "cups", "each" — free-form but consistent |
| store_category  | text      | produce / dairy / meat / pantry / frozen / other   |

## WEEK_PLANS

One row per generated week.

| column       | type      | notes                                       |
|--------------|-----------|------------------------------------------------|
| id           | integer PK |                                                |
| week_start_date | date   | the Monday (or chosen start day) of the week    |
| created_at   | timestamp |                                                |

## PLAN_DAYS

One row per day within a week plan — the calendar input and the assigned
recipe live together here.

| column               | type      | notes                                            |
|----------------------|-----------|-----------------------------------------------------|
| id                   | integer PK |                                                    |
| week_plan_id         | integer FK → week_plans.id |                                    |
| day_of_week          | text      | e.g. "monday" .. "sunday"                          |
| date                 | date      |                                                    |
| is_busy              | boolean   | from the weekly calendar input                     |
| dinner_ready_time    | time      | default 18:00, overridable per day                 |
| recipe_id            | integer FK → recipes.id, nullable | the assigned recipe for this day |

Swapping a day's recipe = updating `recipe_id` on its `plan_days` row. This
does not touch other days or require regenerating the week.

## COOK_HISTORY

Append-only. Populated only by business-logic operations (e.g.
`finalize_plan()`, `mark_day_cooked()`), never by UI rendering code — see
`docs/AGENT_INSTRUCTIONS.md` on duplicate-record protection.

| column       | type      | notes                                             |
|--------------|-----------|------------------------------------------------------|
| id           | integer PK |                                                      |
| recipe_id    | integer FK → recipes.id |                                        |
| plan_day_id  | integer FK → plan_days.id, nullable | the plan day this record came from |
| cooked_on    | date      |                                                      |
| created_at   | timestamp |                                                      |

`last_cooked_at` for a recipe (used by the rotation weighting in
`PRODUCT_SPEC.md` §9) is derived as `MAX(cooked_on)` from this table per
`recipe_id` — it does not need its own column on `recipes`.

## AI Assist (Optional)

No new persistent tables are required for this. The AI-assist module (see
`PRODUCT_SPEC.md` §15) is a service-layer helper only:

- recipe import produces a draft that, once the user confirms it, is written
  through the normal `recipes` / `recipe_ingredients` insert path — no
  separate "draft" table
- ingredient categorization only suggests a value for
  `recipe_ingredients.store_category` before the row is saved
- swap-intent and shortcut suggestions are computed on request and are not
  stored

If a future milestone needs to cache import results or model output, add a
decision entry and a table then — do not add one speculatively now.

## Entity relationship summary

```
RECIPES ──< RECIPE_INGREDIENTS

WEEK_PLANS ──< PLAN_DAYS >── RECIPES

RECIPES ──< COOK_HISTORY >── PLAN_DAYS
```
